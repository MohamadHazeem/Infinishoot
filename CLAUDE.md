## Commands
- `npm run dev`: dev server at http://localhost:5173
- `npm run typecheck`: strict TypeScript check (must pass)
- `npm run build`: typecheck + production build to `dist/`
- `npm test`: unit tests in tests/*.test.ts (bundled with rolldown, run in Node)
- `npm run smoke`: headless whole-game smoke test (jsdom, autoplay bot through every mode and hero, fails on any runtime error); CI runs both
- `npm run shot -- "?test&stage=4&boss" shots/x.png`: headless screenshot of a test link (src/dev/testLinks.ts); see CONTRIBUTING.md for the link options
- `npm run coop`: two headless game instances play online co-op (host + client via the PeerJS broker, dev bot on both via `botAuto`), forced boss/arena/skill situations, host-vs-client state checks and screenshots in shots/coop/; fails on page errors or lasting desyncs (notes/lanes/coop.md)
- `npm run fuzz -- --runs 300` (headless Chromium) / `-- --jsdom --runs 1000`: crash fuzzer, random test-link combinations (src/dev/fuzzLinks.ts, `&monkey` adds random keys and clicks) played by the bot, errors deduped by stack; `npm run soak -- --minutes 30` (`--churn`: a fresh run per sample): long god bot run, flags leaks, slowdowns and stalls (notes/lanes/crashfuzz.md)
- `npm run migrate`: host migration check: four headless players online, the host's page killed mid-fight and the new host's mid-shop; the run must carry on with the same builds, shop and gold (`--runs 3`, `--players 3`; notes/lanes/hostmig.md)
- `npm run coop4`: four-player stress test (host + 3 clients, one with added latency, all on the dev bot): drop-out/drop-in, revive pool, team ultimate, emotes, mech, world event, boss and owned chests, shop/route into stage 2, then Versus Swarm and local co-op smoke checks; checks every client against the host and for stuck screens, scheduled in the host's simulated seconds so a loaded machine only makes it slower (notes/lanes/coopstress.md)
- `npm run coop8`: eight in-process jsdom peers play online co-op (snapshot size and build-time budgets, host-vs-client checks, one owned boss chest per hero); fails loudly if it ends without its PASS/FAIL line
- Other checks: `npm run voicechat` (two pages with a fake mic), `npm run replay` / `npm run visual` (run replays with checksums, 20 visual baselines), `npm run sweep` (four-kit balance sweep, 25% tolerance), `npm run loadtime`, `npm run bench`; `npm run server:deploy` deploys the online Worker (docs/ONLINE.md)
- Workflow rules for people and agents: CONTRIBUTING.md (Codex reads AGENTS.md). Most Game methods live in src/game/systems/*.ts.
- `npm run app`: build and open the Electron desktop app
- `npm run dist`: build the portable Windows exe to `release/InfiniShoot.exe` (Electron, electron/main.cjs).
- `npm run dist:mac`: build unsigned Mac dmgs (arm64 + x64) to `release/`. The exe and the dmgs are the shipped builds; there is no itch.io build.
- CI (`.github/workflows/ci.yml`) typechecks, tests and smoke-tests every push; pushing a `v*` tag runs `.github/workflows/release.yml`, which builds the exe and the dmgs and attaches them to a GitHub Release. The web build deploys to GitHub Pages on every push to main (.github/workflows/pages.yml) while the repo is public.

## Conventions
- Gameplay simulates in 2D on the XZ plane; meshes are presentation only and interpolate between `prev` and `pos`.
- All scene materials use `createRetroMaterial` (src/render/retroMaterial.ts). Global look values live in `retroGlobals` and are shared by reference, so don't `.clone()` retro materials (cloning breaks the sharing); create new ones with the factory.
- Colour management is off: author colours as the hex values you want on screen.
- Tunable values live in exported `*Tuning` objects and get wired into src/ui/debugPanel.ts.
- In dev builds `window.game`, `window.cheats` and the autoplay bot are exposed: `botRun(seconds, god)` simulates headlessly and returns a balance/perf report (per-stage level and loadout ranks, boss kill times, first evolution). Note `window.game` is the canvas element in production (named access by id).
- Instanced pools must upload only live slots: call `commit(attr, count)` (src/render/instancing.ts) instead of setting `needsUpdate`.
- Many-of-a-kind things (enemies, bullets, particles, decals) render via `InstancedMesh`. Per-instance hit flash uses `createRetroMaterial({ instanceFlash: true })` plus an `instanceFlash` vec4 attribute.
- Content is data in src/data/: weapons (full params per level), passives, Mods, enemies, biomes and achievements. Weapon behaviour lives in src/game/weapons/ (one class per weapon, registered in index.ts) and only touches the game through `WeaponCtx`.
- Mods (src/data/mods.ts) are data plus hook functions typed in src/game/modTypes.ts; src/game/synergy.ts runs the ordered slots (Echo resolution, flag sums, damage pipeline, triggers). New Mod behaviour goes through `ModApi`/`ModFlags`, not direct Game access. Weapons read Mod flags via `ctx.flags`. Mods level up in the shop (`Synergy.upgrade`, cap `modMaxLevel(def)`, cost `Hero.upgradeCost`): a level-N slot runs its hooks N times, but damage applies once per slot as `(amount + add*n) * (1 + (mult-1)*n)` so levels and Echo never compound; sells refund half of `slot.paid`. An upgradable Mod's `desc` is a function of its level (read it with `modDesc(def, lv)`) so the shop can show the current and next level's numbers.
- `game.stats` is the live stats object (static + per-step Mod effects); call `recomputeStats()` after passives or Mods change, never reassign it.
- All damage goes through `ctx.damage()` / `Game.damage`, which applies stats, crits and freeze-shatter and tracks the per-weapon damage breakdown.
- Rarity (src/data/rarity.ts: common, uncommon, rare, legendary) is set on every weapon, passive and Mod. Level-up weights are kind weight x `rarityWeight(rarity, luck)`; upgrades use their item's own rarity rate (a legendary's levels are legendary-rare). Luck (`stats.luck`) lifts rarer tiers, Mods in the shop and gear drops. UI styles tiers with `r-<rarity>` classes (cards, Mod cards, HUD slots, badges) and `r-text-<rarity>` for labels.
- Utility drops (heart, magnet, gear, nuke) are scaled by `min(1, dropTuning.dropRef / director.targetAlive)` so drops per minute stay flat as hordes grow. The Nuke reuses the bomb wave (`hero.bombNuke`). Runs open with a starting shop (`preShop`, `economyTuning.startGold`, leftover gold is wiped). The camera zooms out with the mouse wheel (`CameraRig.wheel`, fog pushed back with it); co-op interest radius (`INTEREST`) covers the zoomed-out view.
- Loadout (src/data/loadout.ts): before a run each player picks a left click (`slot: 'primary'`), a right click (`slot: 'secondary'`) and a special on the LOADOUT screen (`settings.loadout`, sent to the host in `hello`/`loadout` messages, `hero.loadoutPick`); they're kept all run and never offered as new cards. Auto weapons fill `MAX_WEAPONS` (4) other slots. Loadout items with `tracks` (src/data/tracks.ts) grow through track ranks (deltas added to `levels[0].p`), a two-way evolution fork once `evoAt` ranks are taken (`evos`, weapon classes branch on `evoId`, icons `<id>_evo` / `<id>_evo2`) and repeatable Overdrive ranks; level-up offers of kind 'track' / 'evo' / 'overdrive' carry `pick` ("<item>|t|<track>", "<item>|e|<evo>", "<item>|od"; the special's item is 'sp'). Builds reach clients as `buildKey` strings. Evolution tags count everywhere: weapons get them from `Weapon.tags` / `Hero.tagsOf(source)` (damage without explicit tags uses them). Items without tracks (auto weapons) still use their `levels` ladder. Right-click hits Expose enemies (`statusTuning.exposeTime`/`exposeMult`).
- Specials (Q/E, src/data/specials.ts): `hero.special` {id, level} plus `hero.specialBuild` for specials with tracks (`hero.specialP` gives the params); the meter refills over time (`specialTuning.cooldown` 15 s, divided by the level's `charge`, times `stats.specialCooldownMul` from Battery Pack: `hero.specialCooldown`); the Bomb runs in Game.tryBomb/updateBomb, the rest in src/game/specials.ts through `SpecialApi`. Elites draw health bars via `hud.setEliteBars` (projected in Game.renderEliteBars) and tune aggression with `eliteTuning` (src/game/enemies.ts).
- Loops: every `LOOP_STAGES` (4) stages end with the final boss (Omega Overlord, `omegaTuning`); bossForStage rotates BOSS_ORDER; stageClear on a multiple of 4 is the victory. The Reaper (`directorTuning.reaper*`, needs `director.teamLevel`) is not a boss. Co-op-only passives have `coop: true` and are offered only when `game.coop`; their team auras run in Game.applyTeamAuras. The level-up pick lock is `Screens.canPick(i)` (`pickTuning.lock`); the dev bot bypasses it.
- Map chests spawn over time (`chestTuning`: one every 30 s at a random walkable spot, at most 4 closed; host broadcasts `chestspawn`) and only level passives you own, else a weapon level, else gold. One hit can't take more than `playerTuning.maxHitFrac` of max life. `DamageOpts.fixed` skips stats, Mods, statuses and crits (the Nuke's bite on bosses).
- Boss chests: one per hero, owned (pickup value `OWNED_CHEST` + hero index; the `canTake` filter keeps teammates off it, and a pickup goes to the nearest hero that may take it). The stage clear pulls every chest to whoever may open it (`pickups.vacuumChests`).
- Gears (PickupType.Gear) are level-up rerolls held in `hero.rerollsLeft`, capped at `MAX_GEARS`; at the cap they stay on the ground (the `canTake` filter in Pickups.update).
- The persistent profile (achievements, which unlock auto weapons via `unlockWeapon` and loadout items via `unlockLoadout`, and lifetime stats) is `save` in src/game/save.ts; `unlockedLoadout()` gates the LOADOUT screen and `validLoadout(l, unlocked)`, and achievements with a `lifetime` test are granted from lifetime stats on load. Bump the version and extend `normalize()` when its shape changes, so old saves keep loading.
- PvP (src/game/pvp.ts): the online lobby's host picks CO-OP or PVP (`lobbyKind`). PvP sends `pvpgo` (seed, difficulty); every machine plays that stage as a plain solo run (`role` 'solo' while `game.pvp.net` remembers host/client, effects aren't recorded), and on finishing (or dying) sends its `HeroBuild` (`exportBuild`) in `pvpready`. The host rebuilds everyone (`applyBuild`) and runs the duel over the co-op netcode: no director, chests or revives, a closing ring (`pvpTuning.zone*`). Each hero has an invisible stand-in enemy (`PVP_TARGET`, `EnemyDef.hidden`, `Enemy.pvpOwner`) that other heroes' weapons hit; `Game.damage` routes those to `pvpHit`, which scales them (`pvpTuning.damageScale`) into pending damage that lands as hero hits (i-frames and `maxHitFrac` pace it). A hero's own `ctx.nearest`/`ctx.inRadius` and bullets skip its stand-in. Last one standing wins (`pvpend`).
- Relics (src/data/relics.ts) have a `rarity` and optionally a stat `add` (applied in `Hero.recomputeStats` like a passive); boss drops and the secret shop pick with `rollRelic` (rarity-weighted, Luck helps). Relics are free: the secret merchant offers a pick of 3 (`hero.relicOffers`) on its own RELIC screen that `Screens.showShop` shows before the shop until one is taken; owned relics have their own section in the shop and pause screen, apart from Mods (`ShopView.relics`, `relicChip`).
- Loadout items (both clicks and the special) show no rarity anywhere (`LoadoutItem.rarity` is undefined for them); rarity only matters for auto weapons, items, Mods, relics and level-up cards.
- Multiplayer: `Game` holds team state (stage, XP, score, director) and `heroes: Hero[]` (src/game/hero.ts) with per-player weapons, passives, Mods, gold, offers and shop; `game.hero` is this machine's hero. `role` is solo, host or client. Solo and host simulate everything; clients move their own hero and mirror host snapshots (src/net/peer.ts transport, src/net/codec.ts binary records). On the wire, snapshots go through src/net/snapCodec.ts (compact lossless body that skips unchanged fields, byte deltas for enemy/pickup records, keyframe every 40) and effects through src/net/fxCodec.ts (binary effects bus); new snapshot fields and new effect kinds work without codec changes (a generic fallback), but give a new frequent effect kind a compact case in fxCodec.ts.
- Cosmetic effects go through `game.vfx` (src/game/vfx.ts), never fx/particles/sfx directly, so the host can replay them on clients. Anything gameplay-relevant must run in update(), not render().
- New weapons must implement `net()`/`setNet()` for anything clients need to draw.
- Loadout weapons (`slot: 'primary' | 'secondary'` in src/data/weapons.ts) are the two clicks: the Buster is the default left click (rapid fire) and the Charge Shot (src/game/weapons/charge.ts) the default right click. A def with `evo` treats its last level as an evolution: new name, colour, `<id>_evo` icon and a visual change in the weapon class (`this.evolved`). Upgrades follow the click: left-click weapons honor `this.megaShot(ctx)` (Hair Trigger) and `flags.busterDisabled`; right-click ones honor `this.rightClickSpeed(ctx)`, `stats.chargeDmg`, `flags.chargeSplit`, `flags.overcharge` and `flags.busterDisabled`, and Mods test `isRightClick(source)` instead of `source === 'charge'`. Right-click weapons drive the crosshair reload meter through `ready` (use `startCooldown()`/`tickReady()`) and fire with `armFx()` plus their own `ctx.sound`. Friendly projectiles never use the enemy-bullet magenta (#ff3df0). Lobbed/called-in weapons land at `player.landDist(min, max)` (the cursor; stick aim uses max). Piercing bullets track their last hits via `bullets.hasHit/markHit`. Player bullet `kind` maps to a damage source in `BULLET_KINDS` (game.ts); new bullet colours must be added to `BULLET_COLORS` (codec.ts) or clients draw them yellow.
- `Game` (src/game/game.ts) owns the session: menus, run state and every system. Its modes are title, fight, levelup, cleared, portal, transition and dead. Juice goes through `game.juice.freeze()` / `.shake()` / `.kick()`.
- Auto weapons with a partner evolution (`WeaponDef.evolution`) show it on their cards and their partner item's cards: set `partner` on the Offer (`Hero.partnerOf`), rendered as the evolution strip in screens.ts; tooltips add the same line (`Hero.partnerTip`).
- Level-up cards and HUD/build slots carry a `slot` (`Slot` in src/ui/hud.ts: left, right, special, auto, item, bonus) shown as a coloured ribbon with a pixel pictogram (`slotPicto`) and a matching corner tag; set it on every new offer kind.
- UI is plain DOM: HUD in src/ui/hud.ts, menus in src/ui/screens.ts. Anything navigable gets `data-nav` so `MenuNav` handles keyboard and gamepad.
- UI style is pixel art: only the Sweetie 16 colour variables in style.css, sizes in `--p` (one UI pixel), frames from the shared box-shadow recipe (set `--bg`, `--hi`, `--lo`, `--ring`), no border-radius, blur or gradients-as-shading, and `steps()` animations. Fonts: Jersey 15 (text), Jersey 10 (big numbers, headings, logo), Silkscreen (small labels).
- Item icons come from game-icons.net (CC BY 3.0, credited in README and on the title screen): map an item id to an icon name in scripts/icons.mjs, run `npm run icons`, and render with `iconHtml(id, color, glyph)` from src/ui/pixelIcons.ts (24-pixel sprites: show them at 24, 48 or 72 px). Pick bold silhouettes: fine detail doesn't survive 24 pixels, so check new icons on a contact sheet, and don't reuse an icon for two items.
- Biomes: stages follow `BIOME_ORDER` (src/data/biomes.ts; loop 1 is meadow, dunes, peaks, magma; Neon City, Toy Factory, Sky Fortress and remixes like `meadow:autumn` from loop 2), always via `biomeForStage(stage)`; `&biome=<key>` pins one (`biomeForce`). Biome audio (music, ambience, footsteps) and weather are fields on the biome, not switches on its id. Biome-native enemies set `EnemyDef.biomes`.
- Hero mechanics (Duelist, Furnace, Twin) live in src/game/heroMechs.ts and src/game/systems/heroMechs.ts; every hero needs an ultimate and a voice (recorded barks in src/audio/voices.ts `RECORDED_VOICES`, else the synthesized `HERO_VOICES` in src/audio/voice.ts). Mini-bosses follow boss rules through `bossLike()` (src/game/bossRules.ts); use it instead of `def.boss` for freezes, the Nuke and recycling.
- Screens built outside screens.ts register with `screens.addScreen(name, el, opts | MenuNav, onShow?)` (add the id to `ExtraScreen`). Button prompts come from src/ui/prompts.ts (`prompt(id)`), never hard-coded keys; new HUD panels that should follow UI SCALE go in the selector list in src/ui/hudLayout.ts. Lanes inject their own CSS from their module instead of growing style.css.
- Save v4 adds `meta` (heat, weekly, lore codex, cosmetics), `tips`, `discovered` (EXTRAS > ARSENAL, src/data/arsenal.ts) and `training`. Off-screen threat sounds play on the `threat` bus, which ducking never touches; new dangerous telegraphs should use it (src/audio/sfx.ts, tuning in src/audio/threats.ts).
- Milestone 11 systems (each in src/game/systems/<name>.ts, notes in notes/lanes/): gameplay (mech suit, supply crates, mutations, overload, combo cash-ins, finale, comeback), bossLane (Titan, rematches, boss duel), worldEvents + stealth (mid-stage field events, Night Raid), time (rewind, last stand, bullet time, death replay, clutch revive), coop2 (drop-in/out, revive pool, roles, team ultimate, emotes, help ghosts), modes (rhythm, Pacifist, mini-games, ghost race), cinematics (sky fall, ending, reveals, jackpot, flawless, playable title), versus/localCoop/mp (Versus Swarm, local co-op, lobby browser, team board), sound2 (duel music, crowd, radio DJ, instruments, sound-reactive enemies, surround), graphics (shatter, anime look, reflections, fog, framing, customise). Each lane sends its state in its own snapshot field (`co`, `md`, `cn`, `vs`, `s2`, ...).
- Every D-pad direction is taken: up rewind (`PAD_REWIND`), down team move, left cash-in choice (`PAD_CASHPICK`), right cash-in (`PAD_CASH`); keyboard rewind B, cash-in X / Z.
- Worker endpoints beyond /scores are modules listed in server/leaderboard/routes.js (`async (req, env, url, { json, cors, clean }) => Response | null`); add one line there instead of editing worker.js.
- Persistence goes through src/core/storage.ts, which never throws. Settings and high scores live in localStorage under the `infinishoot.` prefix.
- Player caps come from `lobbyCap(kind)` (src/game/eightp.ts): co-op, weekly, raid, race and PvP take `COOP_MAX_PLAYERS` (8), Versus 4; never hard-code 4. Up to 8 spectators sit on top (src/game/systems/spectate.ts). Scaling past 4 players is in eightp (the identity up to 4).
- i18n (src/i18n): English is the base catalog (`en.ts` plus per-lane files spread into it); Arabic and the five other languages load lazily, so `setLanguage()` is async: tests must `await setLanguage('ar')`. Every visible string goes through `t()` / `localize()`; tests/i18n.test.ts is strict (missing Arabic fails; `I18N_STRICT=0` only for a local inventory). Player names, chat and room codes stay literal (wrap them in `bdi`).
- HUD panels in the corners are placed by one layout pass (src/ui/hudLayout.ts `resolveDock`): register new corner panels there instead of positioning them by hand. Toasts go through the queue in src/ui/toastQueue.ts (one at a time, held while a title card or boss intro is up).
- Save is version 10; each feature normalizes its own fields on load, and separate stores (challenges, trials, records) use their own normalized keys rather than growing the save shape.
- Milestone 12 (v2.0) systems each live in src/game/systems/<lane>.ts with notes in notes/lanes/<lane>.md; the briefs that built them are in docs/parallel-builds/v2.0.
