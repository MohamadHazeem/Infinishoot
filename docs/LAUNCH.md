# InfiniShoot 3.0 owner checklist

Record the app ID, candidate BuildID, demo BuildID, review results and release decision in the private release record. Use the same candidate for store captures, Deck testing and promotion.

- [ ] **Steam app and store.** Complete partner onboarding, create the app and demo, assign Windows/macOS depots and packages, and test a fresh install from a second account. Publish achievement definitions, rich presence and Auto-Cloud settings. Approve regional prices, content survey, bilingual copy, capsules, the in-engine trailer and screenshots. Set the wishlist target before announcing the date. Submit the page and build for Valve review. [Project Steam runbook](STEAM.md) · [Valve release process](https://partner.steamgames.com/doc/store/releasing)
- [ ] **Workshop.** Enable ISteamUGC uploads and configure Workshop visibility on the owner app. From a private test branch, upload one mod pack and one playable arena with **Upload private draft**. Accept Valve's agreement, set test visibility, and subscribe from a second authorized account. After Steam downloads the items, restart, enable the pack in Settings, restart again, and play or host the arena from the Arena Editor. Unsubscribe, restart and check both libraries. Test a missing install and a mismatched co-op pack. Publish the Workshop hub once these checks pass. [Workshop implementation guide](https://partner.steamgames.com/doc/features/workshop/implementation)
- [ ] **Physical Steam Deck.** Set a default gamepad layout. On a clean Deck at 1280×800, use the built-in controls from first launch through settings, loadout, combat, shop, game over, Collection → Patch Notes and back. Try entering and cancelling a lobby name and code with the on-screen keyboard, including Arabic. Check glyphs after wake and after using an external controller. Read subtitles and small labels at arm's length, test suspend/resume during a run, rejoin co-op, and measure a crowded stage with default settings. Record the Proton version, Deck model and BuildID. Request compatibility review and record Valve's rating before using the badge. [Valve compatibility review](https://partner.steamgames.com/doc/steamhardware/compat)
- [ ] **Steam Next Fest.** Choose an eligible edition in Steamworks and record its registration and build-review deadlines. Register the base game, link the demo, complete review, publish the demo in time for the event, and test the store's install and wishlist buttons using a non-developer account. Assign coverage for player feedback during the festival. Track the roadmap's 90% positive demo target together with the number of responses. [Next Fest](https://partner.steamgames.com/doc/marketing/upcoming_events/nextfest)
- [ ] **Community.** Create the official Discord, name moderators for English and Arabic, publish rules and a reporting channel. Confirm the public bug tracker, roadmap, press kit and store links from a signed-out browser. Test that invitations lead to the intended server. Give a moderator responsibility for launch-day issues.
- [ ] **Certificates.** The signing owner provisions the Windows code-signing identity and Apple Developer ID identity, signs the release artifacts, notarizes and staples the macOS build, and tests downloaded copies on clean machines. Keep credentials in the signing environment. Check the final hashes against the uploaded depots. [Desktop release runbook](RELEASING.md)
- [ ] **Online rollout.** Back up the current database, apply the replay-score migration with the existing Worker migrations, deploy the Worker, then enable the server URL in the candidate. Finish a run twice in a staging environment to check deduplication. Confirm the world goal counts it once. Disconnect the service and verify local scores, the daily card and gameplay still work. [Online runbook](ONLINE.md)
- [ ] **Promotion.** Review open crashes, performance gates, accessibility, language QA and the previous working BuildID. Check two-account invites, achievements and a cross-device cloud restore. Approve launch notes, publish the tested BuildID, and designate who can roll it back.

## What a checked score establishes

The new game submits to `/replay-scores`. The server checks a versioned chain sampled every 15 seconds of authoritative play and at the finish. Each link binds the previous checksum to the two clocks, stage, points, kills, pilot position, life and the existing simulation replay hash. The first link binds the board, game version, hero and seed. The server checks cadence, numeric bounds, challenge seed and agreement with the reported finish. D1 atomically retains the top 100 per board and serves 20. It stores hero IDs, results, dates and a SHA-256 deduplication receipt. The full tape, player names, chat and save files stay off the board.

All inputs to the checksum are public and the client supplies the samples. A modified client can generate a consistent fabricated run. Establishing that every hit or input was legal would require independent simulation or trusted authority. Existing clients can use their original `/scores` boards. New boards start empty and accept only the checked format. Ranked PvP ratings and team standings retain their own rules.
