# Lane menus: menu rework, simple and easy to understand (includes the first 10 minutes)

The owner's words: the menus are "very detailed and very hard to deal with, make them simpler and easy to understand". Today the game has dozens of screens and options grown over 60+ feature lanes (PLAY, MODE/hero/difficulty, LOADOUT, starting shop, EXTRAS with Arsenal, Codex, Wardrobe, Customise, Season, Profile, Achievements, Trials, Story, Jukebox, Run history, tabbed SETTINGS with many rows, online lobby with many options, pause, game over...). You are the designer: rebuild the menu structure so a newcomer understands it at a glance and a veteran gets anywhere in 2-3 presses. Read notes/lanes/menu.md, firstten.md, onboarding.md, uxpass.md, menuhud.md, settings.md, lobby.md, meta2.md, seasonpass.md first.

Part A, audit (before you change anything):
1. Screenshot every menu screen and every path (1280x720, 1920x1080, 844x390; English and `&lang=ar`), count presses to reach each feature, list every screen, option and word a newcomer won't understand. Keep this inventory in notes/lanes/menus.md with a "before" press-count table.

Part B, the new structure (decide it from the audit; this is the direction):
2. Title: at most 5 big items: PLAY, ONLINE (or PLAY WITH FRIENDS), COLLECTION (everything you've unlocked or can unlock: Arsenal, Codex, Wardrobe/Customise, Achievements, Story, Jukebox, Run history, Profile/Season as tabs or sections), SETTINGS, QUIT (desktop only). Everything else moves inside these. One clear visual hierarchy, no wall of buttons, no secondary panels competing for attention (activity/quests/news collapse into one small "NEW" corner card at most).
3. PLAY: one screen that starts a run in one press with your last choices remembered ("CONTINUE WITH: Rookie · Buster/Charge/Bomb · Normal"), with CHANGE to edit hero, loadout and difficulty on a single combined setup screen (not three screens in a row). Modes (Standard first; Endless, Boss Rush, Daily, Gauntlet, Trials, Ascension, Raid...) as one list with one-line plain descriptions; modes not yet unlocked are hidden on a fresh save and appear with a "NEW" badge when unlocked (progressive disclosure, using existing unlock/achievement/FIRST STEPS data, no save-format break; any save with a finished run sees what it has unlocked).
4. ONLINE: host/join by code first, then the lobby browser; the lobby shows the essentials (players, ready, START, difficulty, game type) and puts everything else under one MORE OPTIONS panel.
5. SETTINGS: few tabs with plain names (GAME, CONTROLS, VIDEO, AUDIO, ACCESSIBILITY, ONLINE), the most-used options first, advanced options folded under an ADVANCED section per tab, every option with a one-line plain description, sensible defaults. Remove duplicates; keep every existing setting reachable (nothing lost, just reorganised).
6. Words: plain language everywhere in menus. Jargon (Mods, Heat, Overdrive, Ascension, Relics...) gets a one-line explanation the first time it appears and in its tooltip.
7. First 10 minutes on a fresh save: from launch, the story intro is skippable with one press, the title shows ≤ 4 options, PLAY starts a sensible default run (training offered once) in ≤ 2 presses and ≤ 30 s. Nothing a newcomer can't use yet is shown.
8. Consistency: one menu shell (title bar with BACK on the same place and key everywhere, same button sizes, same focus style, same descriptions area), keyboard/mouse/gamepad/touch all work (data-nav, prompts from src/ui/prompts.ts), Arabic RTL mirrored, fits 1280x720 and phones (keep the menuFit/menuhud work and tests passing; extend them).
9. Keep the pause menu simple (RESUME, SETTINGS, the build view, QUIT); another lane is adding a REPORT A PROBLEM button to the pause menu and game-over screen at the same time: leave a clear slot for it and don't restyle those two buttons.

Done when: the "after" press-count table shows every feature in ≤ 3 presses from the title (most in 1-2), the title has ≤ 5 items (≤ 4 on a fresh save), the setup to start a run is one screen, every setting is still reachable, an independent look at the after screenshots finds no screen that needs scrolling at 1280x720 except long lists with the MORE cue. Add tests/menus.test.ts (menu tree: every old feature reachable, press counts, fresh-save disclosure rules, settings coverage) and keep tests/uxpass.test.ts and tests/uipolish.test.ts passing (update their expectations where the structure changed on purpose, and say so).

Owns: src/ui/screens.ts (title, PLAY, mode, loadout, extras, settings sections), src/ui/menu*.ts, src/ui/menuFit.ts, src/ui/menuHud.ts, src/ui/settings*.ts, the menu screens of other lanes that register through screens.addScreen (their markup and layout, not their game logic), src/ui/onboarding*.ts and firstten*.ts menu parts, src/game/systems/party.ts / lobby UI parts, i18n entries, tests/menus.test.ts, tests/uxpass.test.ts, tests/uipolish.test.ts, notes/lanes/menus.md.
