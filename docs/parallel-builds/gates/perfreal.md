# Lane perfreal: real-GPU performance and load time

Goal: prove (or fix) the 60 fps target on real hardware and the load-time target, with numbers anyone can reproduce. So far performance was only measured headless. Read notes/lanes/perf.md, perf2.md, perfload.md, gfx3.md and scripts/bench.mjs, scripts/loadtime.mjs first.

This Mac is real hardware (Apple Silicon, Metal): use headed or GPU-enabled Chromium (not SwiftShader) and the Electron app.
1. A reproducible real-GPU benchmark: `npm run bench:real` that opens the game in a GPU-backed browser at 1920x1080 and 1280x720 for each quality preset (LOW, MEDIUM, HIGH, and HIGH with shadows), runs fixed heavy scenes (the existing heavy bench: 150+ / 300 enemies, 500 / 1,000 projectiles, a boss fight with effects, 4-hero co-op scene, the Titan, a night stage with fog and reflections), and records frame-time percentiles (median, p95, p99), dropped frames, CPU vs GPU time where measurable, draw calls, triangles, JS heap. Output a markdown + JSON report in notes/perf/real-<date>.md. Do it in Electron too (the shipped build): one run of the same scenes through the packaged app if feasible, else document why not.
2. Find the top costs in the worst scenes (Chrome tracing / performance profiles) and fix the ones that are safe in your owned files: render passes, post effects, instancing, overdraw, material/shader cost, auto-quality thresholds (auto quality should step down before frames drop, and back up with hysteresis). Measure before and after each change.
3. Load time and size: measure the production build (`npm run build`): initial JS/CSS/asset bytes over the wire, time to title and to first fight on a simulated "broadband" and "slow 4G" profile, and the Electron app's cold start. The brief's target is under 5 MB initial and under 3 s to title on broadband: if it's over, cut it (code-splitting, lazy audio/locale/tools, asset compression) without changing what players see.
4. Low-end safety: a forced "low-end" profile (CPU throttling 4x in Chromium) must still hold 30+ fps on LOW; document the result.
5. Write a performance budget in notes/perf/BUDGET.md (ms per system, draw calls, bytes) and make `npm run bench:real -- --check` fail when a scene is over budget, for future gates.
Owns: src/render/** (except anything another lane names), vite.config.ts chunking/compression settings, scripts/bench*.mjs, scripts/loadtime.mjs, new scripts/benchReal*.mjs, notes/perf/**, tests/perfreal.test.ts, notes/lanes/perfreal.md, package.json scripts lines (add only). Do not edit src/game/juice*, src/game/vfx.ts or menus (firstten2 lane), electron/** (steam lane) or server/** (telemetry lane). If a fix needs one of those, describe it in your notes for the lead.
