# Lane telemetry: opt-in playtest telemetry and one-tap "report a problem"

Goal: every playtest run tells us where players die, what they pick and how long runs last, and any player can send a problem report with their run replay attached, so tuning (Gate 2: making the game hard) is driven by real data instead of the dev bot. Read notes/lanes/ci2.md (run replays with checksums), notes/lanes/deploykit.md and docs/ONLINE.md (the Worker, routes.js, deploy script) first.

Privacy is non-negotiable: telemetry is OFF until the player says yes. First launch (and once for existing saves) shows a short, friendly consent screen (EN/AR): what is collected, that it's anonymous, YES / NO, changeable in SETTINGS > GAMEPLAY (or the most fitting tab) as "SHARE PLAYTEST DATA". Anonymous random install id (crypto.randomUUID, stored locally), no names, chat, room codes, IP addresses or free text except what the player types into a report. A "DELETE MY DATA" button sends a delete request for that install id.

Build:
1. Client (new src/game/systems/telemetry.ts + src/net/telemetryClient.ts or similar):
   - A per-run summary posted once at run end (death, victory, quit to title): version, mode, difficulty, ascension/heat, hero, loadout, solo/co-op/AI squad and team size, stage and loop reached, run time, level and loadout ranks per stage, every level-up offer and pick (ids only, with the alternatives offered), shop purchases, Mods/relics held at death, boss fights (id, time to kill or death), damage taken by source per stage, cause of death (enemy/boss/hazard id, the hit that killed, life before the hit), rewinds/last stands/revives used, average/worst frame time and quality preset, platform (web/electron-win/electron-mac, mobile or not), language. Keep it under ~8 KB.
   - Death context: the last 10 seconds of hits taken (source, amount, life after).
   - Batched and offline-safe: queued in storage when there is no server or no connection, flushed later, capped queue, never blocks the game, never throws.
   - Sends only when consent is yes AND a server URL is configured (VITE_LEADERBOARD_URL, same as the other online features).
2. Report a problem: a button on the pause menu and the game-over screen ("REPORT A PROBLEM"), keyboard/gamepad navigable: category (bug, too hard, too easy, confusing, performance, other), optional text (500 chars), checkboxes "attach replay of this run" (default on; uses the existing replay recorder/gzip export) and "attach a screenshot" (canvas capture, downscaled JPEG/WebP ≤ 300 KB). Works without consent to telemetry (it's an explicit send), but says what it sends. If no server is configured, offer SAVE REPORT TO FILE instead.
3. Worker (server/leaderboard/telemetry.js, one line in routes.js): POST /telemetry/run, POST /telemetry/report, POST /telemetry/delete, GET /telemetry/summary (admin only). Storage: Cloudflare D1 (not KV: KV free tier allows only 1,000 writes a day). Schema migration file in server/leaderboard/migrations/. Validation, size limits (run 16 KB, report 1.5 MB with replay), per-install rate limits, version allow-list. Reports' replay/screenshot blobs stored in D1 as compressed blobs (D1 row limit 2 MB) or split rows, decide and document. Admin endpoints require a bearer token from a Worker secret `TELEMETRY_ADMIN_TOKEN` (never in the repo).
4. Deploy script: extend scripts/server-deploy.mjs (and the wrangler template) to create/reuse the D1 database `infinishoot-telemetry`, bind it, apply migrations, and remind to set the admin secret (`npx wrangler secret put TELEMETRY_ADMIN_TOKEN`). Nothing deploys automatically. `npm run server:dev` must work locally with a local D1.
5. Playtest dashboard: a static page tools/playtest-dashboard/index.html (no build step, no framework, no CDN dependency) that takes the server URL and admin token (kept in sessionStorage only) and shows: runs per day, median run length, stage reached distribution, top 10 causes of death (by stage), boss kill time and death rate per boss, pick rates and win rates per item/hero/loadout, difficulty breakdown, worst frame-time platforms, and the report inbox (category, text, download replay/screenshot). Simple tables and bar charts drawn with inline SVG.
6. Tests: tests/telemetry.test.ts (consent gating, payload shape and size cap, queue/flush/cap, no PII fields, report packaging), a worker test against the route handler with a fake D1 (pattern: existing worker tests), and the dashboard's aggregation functions.
7. Docs: a "Playtest telemetry" section in docs/ONLINE.md (what is collected, how to read the dashboard, how to delete data) and notes/lanes/telemetry.md.

Owns: src/game/systems/telemetry.ts, new src/net/telemetry*.ts, new src/ui/report*.ts and src/ui/consent*.ts, server/leaderboard/telemetry.js, server/leaderboard/migrations/**, scripts/server-deploy.mjs, scripts/server-dev.mjs, server/leaderboard/wrangler.template.toml, tools/playtest-dashboard/**, tests/telemetry*.test.ts, docs/ONLINE.md, notes/lanes/telemetry.md. Small additive edits: routes.js (one line), the run-end hook in src/game/systems/runFlow.ts, pause/game-over buttons in screens.ts/onboarding.ts, a settings row, i18n entries.
