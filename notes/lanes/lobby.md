# Lane: lobby (getting friends together)

## What players get
- **Invite links.** The host's lobby has **COPY INVITE LINK**: `<game url>?join=CODE`. Opening it goes straight into joining that game (the address is cleaned so a reload doesn't rejoin). The web build links to itself. The desktop app (file://) links to the public web build (`WEB_URL` in src/game/lobby.ts, `VITE_WEB_URL` overrides; default https://mohamadhazeem.github.io/Infinishoot/). The JOIN field takes a pasted link as well as a code (the desktop app can't be opened by a link, so friends paste it there).
- **Friend codes.** Every save gets a 5-letter friend code (same alphabet as room codes). With **HOST WITH MY CODE** on (the default), hosting uses it as the room code, so a saved code or invite link works whenever you host. If the code is taken on the broker (`unavailable-id`, e.g. a stale session), hosting quietly falls back to a random code.
- **Lobby upgrade.** Player cards in a 2x2 grid: name, YOU tag, hero, profile level, best stage, kit, skin and pet, ping (green < 90 ms, yellow < 180, red), READY / NOT READY (ready cards get a lime ring). **READY UP** for everyone: when 2+ players are all ready a 3 s countdown starts the run (STARTING IN 3...), and any un-ready cancels it. The host's START GAME still starts at once (force). The host gets one **KICK <NAME>** button per guest: the guest goes back to the title ("THE HOST REMOVED YOU FROM THE LOBBY") and can't rejoin that host for 2 minutes (by player id, or by name for old clients).
- **Chat** (lobby and party screens, a panel on the right; under 1240 px wide it moves below the lobby): six **QUICK CHAT** phrases (pad friendly, sent as an index), and a text field (SAY focuses it, Enter sends, Esc leaves it). Lines are max 60 characters, control and bidi characters stripped, spaces collapsed, and a basic word list (with simple leetspeak and stretched letters, whole words only) is starred. Rate limit: 0.8 s between lines and at most 4 per 8 s per player, checked on the client (instant "SLOW DOWN") and again on the host. Chat is always drawn as text (escaped). The last 30 lines are kept; the chat resets with each new connection.
- **Party after game over.** Online co-op (and weekly co-op) game over shows **PARTY ▶** instead of RETRY. The PARTY screen shows the team result (stage, team level, score, kills, time) and a row per player (hero, damage bar, K.O., vote). Everyone votes **VOTE RESTART** or **BACK TO LOBBY**; when all agree the host does it. The host also has RESTART NOW / LOBBY NOW. RESTART keeps the party, heroes, pets, looks and loadouts and starts a new run (players who left are dropped). BACK TO LOBBY returns everyone to the lobby still connected (ready flags cleared, picks kept). LEAVE PARTY goes to the title alone (the host leaving ends it for everyone, as before). PvP, Versus and local co-op keep their own endings.
- **EXTRAS > FRIENDS** (also PLAY ONLINE > FRIENDS): your friend code, COPY MY INVITE LINK, the HOST WITH MY CODE toggle, ADD A FRIEND (name + code or pasted link), SAVED codes (JOIN, REMOVE) and RECENT PLAYERS (name, last played, runs together, their code; JOIN and SAVE). Recent players are recorded on every machine when a run starts from an online lobby, with the friend code from their lobby card.

## Knobs
- `lobbyTuning` (src/game/lobby.ts): countdown 3 s, ping every 2 s, kick ban 120 s.
- `chatTuning`: maxLen 60, minGap 0.8 s, burst 4 per 8 s window, keep 30 lines. `QUICK_CHAT` phrases.
- `friendsTuning`: 20 recent, 30 saved. `profileLevel`: 1 + floor(sqrt(kills/250 + bosses*3 + runs + achievements*4)), capped at 99.

## How it works
- Pure rules in src/game/lobby.ts (filter, limiter, ready/vote tally, invite links, profile cards, friends list). Game side in src/game/systems/party.ts with per-Game state in a WeakMap; UI in src/ui/lobbyScreen.ts (cards, ready/invite/kick rows, ChatBox, the `?join=` check), src/ui/partyScreen.ts (`party` screen), src/ui/friendsScreen.ts (`friends` screen). Each module injects its own CSS.
- Wire messages, all prefixed `lb` so no lane clashes: client -> host `lbready {on}`, `lbchat {s|q}`, `lbpong {s}`, `lbvote {v}`; host -> client `lbx` (lobby cards: ready, ping, hero, skin, pet, profile, countdown, `you`), `lbchat {n,c,s,sys}`, `lbchatno`, `lbping {s}`, `lbkick`, `lbparty` (party view with `you`), `lbtolobby`. `hello` gains `prof` (profile card incl. friend code); the host peeks at `hello` (records pid and card, refuses kicked players with `full`) and lets the normal handler continue. Lobby and party data are menu-time messages, not snapshot fields.
- Restart builds `game.lobby` from the heroes still in the party (host first) and calls `hostStart()`. Back to lobby does the same, broadcasts `lbtolobby`, and both sides drop to one title hero and `goTitle()` without closing the connection; the next `lobby` message redraws the client lobby.
- The state resets whenever `game.host ?? game.client` changes (`stateOf`), so an old lobby's chat or votes never leak into a new one.
- Save v5 adds `friends` (`cleanFriends` migrates older saves; tests/onboarding and tests/meta now accept version >= 4).

## Unfinished / risky
- No real two-machine test or real network latency; the desktop app can't open `?join=` links (no protocol handler, by design: paste the link or code).
- The word filter is a short English list; it won't catch everything and may star a rare legitimate word. Rate limits are per peer id, so a client that reconnects gets a fresh budget (the kick ban is per player id).
- Friend-code hosting means the same room code every time: someone who has your code can join whenever you host (KICK still works; turn HOST WITH MY CODE off for a random code).
- Recent players only know a friend code if that player's game sends `prof` (this version on); older clients show without a code.
- Text chat needs a keyboard; pads have quick chat. Chat isn't shown during the run (lobby and party only).
- Party restart renumbers heroes when someone left; coop2's per-index player ids are rebuilt by its own join flow and weren't checked further.
